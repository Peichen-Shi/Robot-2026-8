# Lab6 · 无人机视觉定位

无人机拍下前后两张图，能看出自己转了多少、往哪儿飞吗？Lab5 的 SIFT 先在两张图里找同一处细节，Lab6 再用这些点估计相机的运动。有了深度图，还能算出移动了几米。

**本版报告基于 MIT Office 扩展数据片段的 2,214 对相邻画面。** 四种必做方法和一次无 RANSAC 的对照都已运行。

## 在 Ubuntu 上演示

在已配置好的 VMware Ubuntu 桌面终端运行：

```bash
cd ~/lab6_complete
bash demo.sh ARUN3
```

| 看哪里 | 会看到什么 |
| --- | --- |
| RViz 左侧 | 同一场景的深度图和 RGB 图 |
| RViz 中央 | 相机估计位姿和参考位姿，用箭头表示 |
| 底部 ROS Time | 时间在走，表示录包正在播放 |

脚本优先使用扩展录包和对应位姿，终端会显示实际选择的文件。把 `ARUN3` 换成方法表中的参数即可切换。按 **Ctrl+C** 退出。重新计算用 `bash evaluate.sh`。新环境的安装步骤见[复现脚本说明](scripts/README.md)。

## 方法有什么区别

| 方法参数 | 怎么做 | 能算出什么 |
| --- | --- | --- |
| `NISTER5` · Nistér 五点 | 用五对点提出候选，让更多匹配投票 | 旋转、平移方向 |
| `EIGHT8` · Longuet-Higgins 八点 | 用八对点列线性方程，再用 RANSAC 检查 | 旋转、平移方向 |
| `KNOWN2` · 已知旋转两点 | 先给定旋转，再用两对点求移动方向 | 平移方向。本实验用真值旋转模拟已知输入 |
| `ARUN3` · Arun 三点 | 用深度把像点变成三维点，再把前后两组三维点对齐 | 旋转、以米为单位的平移 |
| `NISTER5_RAW` · 五点对照 | 只用一组靠前的描述子匹配提出一次假设 | 旋转、平移方向，用于对照 RANSAC 的作用 |

RANSAC 可以理解为反复抽几对匹配来试算，再看哪一次的结果能得到最多匹配支持。下表中的「内点」是通过几何检查的匹配。

## 2,214 对画面的实测结果

| 方法 | 成功求解 | 旋转误差中位数 | 平移误差中位数 | 内点数中位数 |
| --- | ---: | ---: | ---: | ---: |
| 五点＋RANSAC | 2214/2214 | 0.4978° | 0.7523（方向） | 289 |
| 八点＋RANSAC | 2214/2214 | 0.2309° | 0.4252（方向） | 276 |
| 已知旋转两点＋RANSAC | 2214/2214 | 0°（旋转已给定） | 0.08999（方向） | 267 |
| Arun＋RANSAC | 2214/2214 | 0.02265° | 0.002914 m | 246 |
| 五点无 RANSAC | 2211/2214 | 1.391° | 1.084（方向） | 194.5 |

二维的方向误差在 0 到 2 之间，数值越小表示方向越接近。Arun 的平移误差以米为单位。表中数据来自[统计摘要](results/office_extended/summary.csv)。

第 13–14 页还比较了 P90、阈值内比例，以及五点法使用 RANSAC 前后的差异。
